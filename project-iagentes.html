Voice AI · Reliability

MIL IAgentes

Plataforma de agentes inteligentes orientada a voz, citas y post-servicio. El valor del caso está en las garantías alrededor de los datos y el go-live, no en afirmar clientes reales.

FASE 6 · Synthetic-only
Problema

Una cita no es solo un formulario

Confirmaciones, recordatorios, lista de espera y acciones post-servicio deben evitar duplicados, solapamientos y estados inconsistentes.

Decisión

Diseñar primero las invariantes

RLS, idempotencia, anti-solapamiento, gestión transaccional y patrón Outbox se usan para proteger consistencia antes de añadir más superficie de producto.

Arquitectura

API + datos + dashboard + proveedores

PostgreSQL actúa como base relacional; la API gestiona lógica; React/Vite presenta operaciones; proveedores externos se mantienen desacoplados para poder sustituirlos o probarlos.

Implementación

Suites por dominio

Las pruebas no se presentan como una cifra única sin contexto: existen suites separadas para appointments, post-servicio, dashboard y readiness.

Validación

Regresión global documentada

El snapshot de Orquestador registra 516/516 PASS, TypeScript limpio en 6 workspaces, build de dashboard PASS y npm audit 0.

Resultado

Go-live deliberadamente bloqueado

El proyecto permanece synthetic-only: sin clientes, datos, billing, Google Calendar ni PSTN reales hasta una revisión específica de go-live.
